# 破茧 · 信息视野探索帮助互联网用户主动探索自己尚未充分了解的信息维度的独立 Web App。服务大学生创新竞赛项目。> 本项目不是聊天机器人，也不是学习平台插件。它不擅自诊断用户是否陷入信息茧房，不为了观点冲突而强行推荐低质量内容。## 技术栈- 前端：React + TypeScript + Vite + Tailwind CSS- 后端：Python + FastAPI- LLM：OpenAI 兼容接口（`base_url` / `api_key` / `model` 可配置，默认指向阿里云百炼「千问」）- 检索：真实搜索 API（Tavily / Brave，可配置 provider；未配置密钥时回退 stub）- 数据库：MVP 暂不使用，已预留「仓储层」以便后续迁移到 PostgreSQL## 目录结构```backend/  app/    main.py               # FastAPI 入口 + CORS + 路由注册    config.py             # 环境变量配置（密钥只在服务端）    schemas.py            # 数据结构：维度 / 证据卡片 / 主题地图    routers/              # health、explore    services/      llm.py              # LLM 封装（OpenAI 兼容）      search.py           # 检索器接口（tavily / brave / stub）      topic_map.py        # 主题地图编排（LLM / stub 回退）  tests/                  # pytestfrontend/  src/    api.ts                # 后端请求封装    types.ts              # 与后端 schema 对应的 TS 类型    store.tsx             # 轻量全局状态    pages/                # 首页 / 地图 / 证据 / 报告```## 快速开始### 1. 后端```bashcd backendpython -m venv .venv# Windows (Git Bash / PowerShell):.venv/Scripts/python.exe -m pip install -r requirements.txt# 启动（默认 8000 端口，含交互式文档 /docs）.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000```### 2. 前端```bashcd frontendnpm installnpm run dev   # 默认 5173 端口，/api 代理到 http://localhost:8000```打开 http://localhost:5173 ，在首页输入话题（如「信息茧房」）→ 点击「开始探索」→ 跳转到探索地图页。## 端到端验证后端启动后，可用以下方式验证接口：```bash# 健康检查curl http://localhost:8000/api/health# 生成主题地图（未配置 LLM 时返回 mock:true 的占位维度）curl -X POST http://localhost:8000/api/explore/topics \  -H "Content-Type: application/json" \  -d '{"topic":"信息茧房","goal":"neutral"}'```## 测试```bashcd backend.venv/Scripts/python.exe -m pytest -v```前端类型检查：```bashcd frontendnpm run typecheck```## 环境变量见 `.env.example`。核心约定：- 未配置 `LLM_API_KEY` → 后端返回 **明确标记的占位维度**（`mock: true`、`generated_by: "stub"`），且**不含任何伪造来源或链接**，仅用于打通流程。- 配置 `LLM_API_KEY` → 由模型生成针对该话题的维度（仍标记为「探索方向假设」，非事实）。- `SEARCH_PROVIDER` 支持 `tavily` / `brave` / `stub`；配置 `SEARCH_API_KEY` 后即返回真实来源（`verified: false`，标记「未经人工核验」）。## 数据可信度约定（重要）- **维度**（探索方向）= 模型生成的假设，非事实；`TopicMap.generated_by` / `mock` 明确标记。- **证据卡片** = 必须来自真实检索，携带 `source_url` / `evidence_type` / `applicability` / `limitations` / `verified`。- 无法核验的来源或主张必须标记（`verified: false` + `verification_note`）。- 本项目不虚构引用、论文、链接、统计或结论。## 研究接口预留（后续）- 用户匿名化探索事件记录- 主题覆盖率计算- 语义重复度计算- 来源可核验率- 用户反馈与主动选择记录- 对照实验分组与数据导出以上均为接口预留，尚未实现。## 当前状态**已完成（阶段一 / MVP 骨架）**- 前后端项目骨架与目录结构- `GET /api/health`、`POST /api/explore/topics`、`POST /api/explore/evidence`、`POST /api/explore/sources` 端到端打通- LLM 封装（OpenAI 兼容）+ 明确标记的 stub 回退- 真实检索接入（Tavily / Brave，可配置 provider + 密钥）- 首页 → 地图页 → 证据页 → 报告页的完整前端流程（mock / 真实后端可切换）- 后端测试（health / schema / 证据检索 / stub 返回）**尚未完成**- 来源的人工逐条核验（当前为自动检索，`verified: false`）- 交互式推荐（基于已探索内容的下一步建议）- 数据库（PostgreSQL）迁移- 研究接口（事件记录、覆盖率、语义重复度等，用于对照实验）## 部署**前端**：GitHub Pages（`.github/workflows/deploy.yml` 已就绪；在仓库 Settings → Pages 选 Source = GitHub Actions，并设置仓库变量 `VITE_API_BASE_URL`、`VITE_USE_MOCK`）。**后端**：两条路径任选——- 阿里云 ECS（国内演示推荐，可用学生券/科创包）：见 `deploy/aliyun-ecs.sh`。- Render（自带 HTTPS，最快拿到可访问地址）：见 `render.yaml`。前端连接后端：`VITE_API_BASE_URL` 本地默认 `/api`（走 vite 代理），部署时填后端完整地址；本地纯 mock 演示可设 `VITE_USE_MOCK=true`。
